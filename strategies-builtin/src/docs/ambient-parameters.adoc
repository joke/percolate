== Keying

An ambient binding is identified by a **key**, not a type. The key defaults to the parameter's own simple
name; `@Ambient("key")` overrides it, letting a consumer name its own parameter differently while still
binding the value a provider published:

[source,java]
----
include::example$ambient/RenamedKeyMapper.java[tag=renamed-mapper]
----

The generated call still passes the *provider's* variable:

[source,java]
----
include::example$ambient/RenamedKeyMapperImpl.java[tag=map,indent=0]
----

The declared type is *verified* against the binding wherever a key resolves — never encoded into the key
itself. Two ambient parameters may share a type as long as their keys differ; a key collision between two
`@Ambient` parameters of the same method is rejected (see <<Errors>>).

== Errors

`@Ambient` fails loudly rather than silently declining, because a quiet non-match would either select a
different, unintended producer or surface as an unrelated "no plan" diagnostic pointing away from the actual
mistake. Three mistakes are each reported with their own message naming the key:

[cols="1,2"]
|===
| Mistake | What is reported

| Two `@Ambient` parameters of one method resolve to the same key
| A duplicate-key error naming the key.

| A key resolves, but the binding's type is not assignable to the consuming parameter's declared type
| A type-mismatch error naming the key and both types — never treated as a silent non-match.

| A key has no binding anywhere it could be reached from
| An unbound-key error naming the key — the compile fails outright, rather than the conversion method
  quietly being skipped in favor of a costlier alternative (or a generic "no plan" message).
|===
