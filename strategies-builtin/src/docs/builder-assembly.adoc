= Builder assembly
:navtitle: Builder assembly

Percolate assembles a target either by calling a **constructor** or by driving a **builder**. Builder support
ships for four conventions, so a Lombok `@Builder` type, a protobuf message, a with-style immutable, or a
side-located `<Target>Builder` can all be mapping targets with no configuration.

Whichever form is used, the whole assembly is generated as a single expression, and the ordinary rules apply:
percolate never auto-maps by name, so every produced member still needs a `@Map` directive.

== Only the declared members are set

Builder setters are optional, so a builder needs only to *offer* the members you declare — it may offer many
more. This is the one place builder assembly differs from constructor assembly, where every parameter is
mandatory and the declared members must match the parameter list exactly.

`Person`'s builder also offers `nickname()`, which the mapping below never declares. That setter is simply not
called, and the builder's own default survives:

== Choosing between a constructor and a builder

A type frequently offers both forms — Lombok's `@Builder` emits an all-args constructor alongside the builder —

[source,java]
----
include::example$builders/preference-builder/PreferenceMapperImpl.java[tag=toCoupon,indent=0]
----

[IMPORTANT]
====
The setting is a *preference*, not a restriction. Where the preferred form does not fit a particular target, the
other one is still used rather than the mapping failing: a type with no builder at all still assembles through
its constructor even when the preference names the builder.
====
